Build notes

Layout

Title with Active/Inactive pill, Edit and Delete at right. Summary surface holds Module, Assign to, Priority and one sentence in plain words. Conditions list reads “If … and …”. The position line is new. Count scope, checked against applyAssignmentRule: only active rules of the same module, sorted by ascending priority. “2nd of 5 active Leads rules” means position in that list; the module name changes with the rule. Equal priorities follow the stored order, so the position is the same order the engine tries them in.

Kept as is

Edit goes to /setup/assignment-rules/:id/edit; Delete opens the Modal; confirm-delete-btn and assignment-rule-detail-page stay. Toast and redirect unchanged. Roles: the route allows admin and rep, and AssignmentRuleDetail.tsx shows Edit and Delete to both with no role check. The list is different: AssignmentRules.tsx hides Delete and New Rule from non-admins. This design keeps detail as it is today and does not change permissions. The mismatch is an existing gap for the owner to decide, not part of this restyle.

Delete

Outline-danger in the header, filled danger only inside the dialog, so only one filled danger is ever on screen. This page already uses the Modal. Only the list still uses window.confirm, and its design keeps that.

390 px

Edit and Delete share the row at 44 px; summary fields wrap to two columns; the dialog buttons stack full width with Delete rule on top and Cancel below.
