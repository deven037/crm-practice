New deal

Shown after pressing Create deal with the name left blank. Defaults are already filled in.

Deal name is required. Enter a name to create the deal.
Deal name is required.
Leave empty to save the deal with no account.
Defaults to 30 days from today.
A matching assignment rule may change the owner when you create the deal.
Win probability
50%
Additional details
Fleet size is required.

States and rules

Validation

Errors show after Create deal is pressed. A blank name shows the banner (role="alert") and the same words under the field, with aria-invalid and aria-describedby; focus moves to the name field. Required custom fields show their message beside the field, as in AC6. Nothing typed is cleared. Fields never turn red before they are touched.

Creating

The button is disabled and shows a spinner while saving. On success the person lands on the new deal with the toast “Deal “name” created.” or “… created and auto-assigned.”

Fields and defaults

Name, account, amount, stage, expected close date, owner, win probability, then configured fields: unchanged from today. Defaults: Qualification, current user, 50%, close date in 30 days. Labels sit above every field; none rely on a placeholder.

Roles, bank, responsive

Admin and rep see this page; a viewer who opens the address sees the Forbidden state from the shell design. Only the Create deal fill and the slider accent use the bank colour. At 390 the grid is one column, actions stack with Create deal on top, every control is 44 px or taller, and nothing scrolls sideways.
