How it works

Priority without dragging

Dragging still works with a mouse. Every card also has a Set priority button (arrow, 44 px on phone) opening a four-item menu, so keyboard, touch and screen-reader users never need to drag (AC30). Choosing the current priority does nothing (AC13).

Same header as the inbox

The settings shortcuts (SLA Management, Custom Fields, Customise Page Layout) and every status chip, including Open + In Progress, sit above both views, so switching view loses nothing. The filter applies to the board columns too; a column with no match shows “No tickets”. At 390 px the shortcuts wrap and are 44 px tall, and the chip strip scrolls inside itself.

Empty column

A column with no tickets shows a dashed box reading “No tickets” (AC4). Counts sit beside every column name.

Responsive

1440: four columns, no scroll (AC27). 768: columns scroll sideways inside the board only. 390: one column at a time, 84% wide, snapping; the next column peeks in. The page never scrolls sideways.

Roles

Viewer sees the board, cards open the record, but Set priority is disabled (see ticket-states).

Keyboard

Per column: each card title, then its Set priority button. Escape closes the menu and returns focus to its button.
