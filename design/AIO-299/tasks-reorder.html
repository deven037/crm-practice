Build contract

Admin and rep only, All view only: drag grip and named ▲ ▼ controls. Viewer has no grip, checkbox, move, delete, priority editor or quick-add; there is no reorder state for viewers. Filtered views have no reorder controls. DOM/tab order: checkbox, Move up, Move down, priority editor, Delete. Due text and position are not focusable. Boundary buttons are disabled.

Snapshot the full confirmed order before each move. Show the proposed order immediately. Allow one save at a time; disable filters, quick-add, checkbox, priority, delete and dragging while saving. All move buttons use aria-disabled and remain focusable; ignore activation until settled. Restore only order on failure and re-enable controls. Rejection or proposed 10-second timeout must exit busy state. A timeout does not prove the server rejected the write; reconcile authoritative order before accepting another mutation, and retain the error until reconciliation succeeds.

Use stable task IDs to retain focus after success or rollback. If a successful move makes its initiating button a disabled boundary button, focus its enabled opposite move button. Drag does not move keyboard focus. Success: polite atomic status “<title> moved to position <n> of <total>.” Failure: visible alert is the single assertive announcement “Task order couldn’t be saved. Previous order restored.” Do not also emit a success toast or polite rollback. Clear the prior message before the next result so identical failures are announced. Mount live regions before requests; never announce on initial render.

The frames condense priority into metadata and omit the drag grip to emphasize recovery. Full editable rows and viewer frames remain AIO-283/AIO-292’s contract. Position markers appear during reorder feedback only. No toggle/add/priority rollback is added by this follow-up.
